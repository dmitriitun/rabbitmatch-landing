# Конструктор страниц

Правка строк (`EditableText` + `AdminEditLayer`, см. `docs/auth-and-editing.md`)
меняет **текст, который уже есть на странице**. Конструктор решает другую
задачу: добавить на страницу то, чего в вёрстке нет — свои секции, картинки,
видео, кнопки — не трогая код.

Обе системы работают одновременно и не мешают друг другу: пока открыт
конструктор, на `<html>` висит `rm-building`, и слой правки текста молчит.

## Что он умеет

| | |
|---|---|
| Текст | Tiptap: жирный, курсив, подчёркнутый, зачёркнутый, размер шрифта, цвет, ссылки, выравнивание (влево/центр/вправо/по ширине), заголовки H1–H4, списки, цитата |
| Медиа | Загрузка фото/GIF/видео, ссылка на YouTube/Vimeo/прямой URL, alt, скругление, обрезка или вписывание, подпись, ссылка при клике |
| Кнопки | Надпись, ссылка (внутренняя без языка, `#якорь` или внешняя), три стиля, три размера, новая вкладка |
| Секции | Фон (цвет, картинка, затемнение), ширина контейнера, отступы отдельно для десктопа и телефона, минимальная высота, якорь, светлый/тёмный текст, скрытие целиком или только на телефоне |
| Ещё | Разделитель, отступ-распорка, дублирование, порядок наложения, отмена/повтор, предпросмотр телефона |
| Разделы | Кнопка «Разделы» в верхней панели: создать пункт меню, вложить в него подстраницы любой глубины, добавить подраздел внутрь готовой страницы вроде «Игрокам», переименовать, перенести, скрыть, удалить — см. [`docs/site-tree.md`](site-tree.md) |

## Главное решение: сетка, а не координаты

Элемент **не** хранит `left: 740px`. Секция — это CSS Grid: 24 колонки на
десктопе, 8 на телефоне, ряд — 12px. Элемент занимает прямоугольник ячеек.

Шаг сетки половинный начиная с версии 2 документа. На 12 колонках минимальное
движение вбок по контейнеру в 1200px составляло 100px — шире, чем большинство
того, что вообще хочется подвинуть. 24 делится на 2, 3, 4, 6, 8 и 12, то есть
выражает всё, что выражала прежняя сетка, плюс позиции между её делениями.

Старые документы не переезжают: `normalizeDoc` при чтении удваивает все
координаты документа версии 1, так что страница оказывается ровно на тех же
пикселях, что и была, и только получает промежуточные остановки. Обратно в базу
это пишется при первом же сохранении из конструктора.

Мышью это ощущается как свободное перетаскивание — курсор тащит рамку, она
прилипает к ближайшей ячейке, — но в базу попадает **доля контейнера**, а не
пиксели. Отсюда следуют три свойства, ради которых всё и сделано:

1. **На телефоне ничего не разъезжается.** Мобильная раскладка — базовая, а
   десктопная сетка накладывается сверху. Что бы ни натащил админ, на узком
   экране элементы выстраиваются в столбик.
2. **Длинный текст не наезжает на соседей.** Ряды объявлены как
   `minmax(12px, auto)`: если текст перерос нарисованный прямоугольник, ряды
   растут и раздвигают то, что ниже.
3. **Порядок в HTML = порядок на экране.** При сохранении элементы
   сортируются по (ряд, колонка). Мобильный столбик, порядок чтения с
   клавиатуры и порядок для поисковика — одно и то же.

Ширину и выравнивание на телефоне можно задать отдельно (панель справа,
блок «На телефоне»), как и спрятать элемент на одном из устройств. Порядок на
телефоне отдельно **не** настраивается — именно он и есть та единственная
вещь, которая гарантированно не ломается.

### Предпросмотр телефона честный

Брейкпоинт объявлен через `@container`, а не `@media`, и контейнер стоит на
обёртке слота. Поэтому рамка шириной 390px на большом мониторе раскладывается
ровно так же, как настоящий телефон, — переключатель в верхней панели
показывает результат, а не приближение.

## SEO и ИИ-поисковики

- Всё, что собрано конструктором, рендерят **серверные** компоненты. В HTML,
  который получает краулер, лежат настоящие `<h2>`, `<p>`, `<ul>`, `<a href>`,
  `<img alt width height>`.
- Посетителю не приходит **ни байта** JavaScript конструктора: редактор — это
  `dynamic()`-импорт за проверкой прав, он грузится только по клику админа.
- `<h1>` конструктор умеет, но нужен он только на странице, целиком собранной
  из документа: у обычной страницы `h1` уже есть, и второй разбил бы цель
  ранжирования. Вкладка «SEO и AI» в панели статистики сообщает, если их
  оказалось два.
- Размеры картинок сохраняются при загрузке и попадают в `width`/`height`,
  поэтому страница не прыгает по мере подгрузки.
- Внутренние ссылки пишутся без языка (`/pricing`) и получают префикс при
  рендере — `/ru/pricing` или `/en/pricing`.

## Как это устроено

```
страница (server)                    админ (client, по клику)
  BuilderSlot page="/" slot="top"      BuilderLauncher → dynamic(BuilderEditor)
        ↓                                        ↓
  loadBuilderDoc(page, locale)          GET /api/builder?page=&locale=
        ↓  кэш 60с, при недоступной БД — пусто            ↓
  BuilderSectionView (server HTML)      правка в памяти + undo/redo
        ↓                                        ↓
  <div data-rm-slot-server>            PUT /api/builder  → normalizeDoc
  <div data-rm-slot-mount>  ←── портал   → page_layouts → revalidatePath('/')
```

| Файл | Что в нём |
|---|---|
| `src/lib/builder/types.ts` | Схема документа и константы сетки |
| `src/lib/builder/normalize.ts` | **Единственные ворота** между вводом и рендером |
| `src/lib/builder/store.ts` | Чтение/запись `page_layouts` + кэш |
| `src/lib/builder/media.ts` | Что принимает библиотека медиа, разбор ссылок на видео |
| `src/components/Builder/nodes.tsx` | Рендер (общий для страницы и для холста редактора) |
| `src/components/Builder/BuilderSlot.tsx` | Точка вставки на странице (server) |
| `src/components/Builder/BuilderLauncher.tsx` | Кнопка «Конструктор» (единственный клиентский код на странице) |
| `src/components/Builder/editor/*` | Редактор: холст, панель, текст, медиа |

### Почему нет санитайзера HTML

Текст хранится не строкой HTML, а JSON-деревом ProseMirror. `normalize.ts`
обходит его и оставляет только известные узлы и метки с проверенными
атрибутами; `nodes.tsx` собирает из этого дерева React-элементы. Пути от
сохранённого контента к сырой разметке просто нет — экранировать нечего.

Проверяются: цвета (hex/rgb/`var(--…)`), размер шрифта (8–200px), адреса
(`/путь`, `#якорь`, `http(s)`, `mailto:`, `tel:` — всё остальное отбрасывается,
включая `javascript:`), размеры прямоугольников, длины строк.

## Медиа

Файлы лежат в Postgres (`media_assets`), отдаются через `/api/media/<id>`, где
`id` — SHA-256 содержимого. Поэтому URL кэшируется навсегда (`immutable`), а
повторная загрузка того же файла ничего не создаёт заново.

Ограничения: картинки до 8 МБ, видео до 25 МБ. Порог для видео низкий
намеренно — байты идут через Node-процесс, который на Railway оплачивается по
памяти (см. `docs/performance.md`). Длинное видео вставляйте ссылкой:
конструктор понимает YouTube и Vimeo и превращает их в `<iframe>` сам.

SVG не принимается: это исполняемый формат, и безопасно принимать чужой SVG
можно только с санитайзером, который придётся вечно поддерживать.

## Перенос страницы в конструктор

Слоты сверху и снизу добавляют секции **рядом** с написанной руками
страницей. Перенос делает другое: страница целиком начинает собираться из
документа.

Кнопка «Импортировать страницу» в верхней панели читает страницу такой,
какой она сейчас отрисована в браузере, и записывает её документом:

- каждая `<section>` становится секцией со своим фоном, отступами, шириной
  контейнера и тоном текста — всё снимается с вычисленных стилей;
- заголовки, абзацы и списки становятся текстовыми блоками; жирный, курсив
  и ссылки сохраняются, у ссылок отрезается языковой префикс;
- карточка переносится **одним** блоком вместе со своей заливкой, рамкой,
  скруглением и внутренними отступами — иначе от неё осталась бы голая
  типографика;
- картинки переносятся с `alt`, размерами и кадрированием;
- ссылки, нарисованные как кнопки, становятся блоками-кнопками;
- положение каждого блока считается из его реального прямоугольника на
  экране и переводится в колонки и ряды сетки.

Два следствия, о которых стоит знать заранее.

**Импорт измеряет, а значит его надо запускать на широком экране.**
Записывается десктопная сетка; мобильная раскладка выводится из неё, и все
блоки получают полную ширину на телефоне.

**Импорт — это приближение, а не перенос один в один.** Переезжают карточки,
заголовки, картинки и кнопки; точные внутренние отступы компонентов — нет.
Результат — заготовка, которую дальше двигают мышью. Собственно ради этого
переход в конструктор и делается.

После подтверждения документ сохраняется с флагом `takeover`, страница
перезагружается и дальше рендерится из него. Кнопка «Вернуть исходную»
снимает флаг: страница снова собирается из кода, а секции конструктора
остаются сохранёнными и возвращаются в любой момент.

### Что перенос забирает

Это осознанный размен, а не побочный эффект:

- **Тексты уезжают из `messages/*.json`.** Ночной автоперевод EN→RU их
  больше не видит: русская и английская версии страницы ведутся отдельно,
  каждая в своём документе.
- **Структура заголовков становится ручной.** `h1` в конструкторе разрешён
  именно для этого — но следить, что он на странице один, теперь некому,
  кроме автора.
- **JSON-LD продолжает описывать тексты из каталога.** `PageSchema` и
  `JsonLd` вынесены за пределы `PageBody` и рендерятся всегда, но читают
  они по-прежнему `messages/*.json`. Если правки в конструкторе разойдутся
  с каталогом, разметка начнёт описывать не то, что на странице.

Что перенос **не** трогает: `generateMetadata`, canonical, `hreflang` и
OG-картинку. Они описывают страницу, а не наполняют её, и остаются в коде.

## Где можно строить

`BuilderSlot` стоит на восьми написанных руками страницах — `/`, `/players`,
`/organizers`, `/coaches`, `/venues`, `/padel`, `/pricing`, `/faq` — по два
места на каждой: `top` (над написанным руками контентом) и `bottom` (под ним).

**И на каждой странице дерева разделов**, где `top` — это и есть тело
страницы: он стоит между заголовком с хлебными крошками и списком вложенного
(на разделе) или блоком «предыдущая/следующая» (на статье). Поэтому написать
статью Академии — тот же жест, что поправить любую другую страницу сайта.

Чтобы добавить слот на новую страницу, написанную кодом, поставьте в её
`<main>`:

```tsx
<BuilderSlot page={PATH} slot="top" locale={locale} />
```

Документ хранится отдельно для каждого языка: русская и английская версии
страницы правятся независимо, как и строки в `content_overrides`.

## Проверка полного цикла

С живой `DATABASE_URL` и админской сессией:

1. `npm run dev`, войти админом, открыть любую страницу из списка выше.
2. Внизу слева — кнопка «Конструктор». Нажать.
3. «Добавить секцию» → «Снизу страницы». Появляется секция с двумя текстами.
4. Двойной клик по тексту — панель форматирования. Выделить слово, нажать
   «Ж», сменить размер, поставить ссылку.
5. Потащить элемент мышью — он прыгает по ячейкам сетки. Углы тянут размер.
6. «Добавить элемент» → «Фото / видео / GIF» → загрузить файл, вписать alt.
7. Переключить на телефон (иконка в верхней панели) — проверить, что ничего
   не разъехалось, при необходимости поправить «Ширина» и «Выравнивание» в
   блоке «На телефоне».
8. `Ctrl+S` или «Сохранить». `Ctrl+Z` отменяет, `Ctrl+Shift+Z` возвращает.
9. «Закрыть», открыть страницу в инкогнито — секция на месте.
10. DevTools → «Просмотр кода страницы» (не Elements): в исходном HTML должны
    быть `<h2>`, `<p>`, `<img alt=… width=… height=…>`. Если их там нет —
    что-то отвалилось на сервере.

## Что осталось за рамками

- **Черновики.** Сохранение публикует сразу. Нужен предпросмотр до
  публикации — добавьте второй столбец `draft jsonb` в `page_layouts`.
- **История версий.** Undo живёт в памяти вкладки и умирает вместе с ней.
- **Перенос между языками.** «Скопировать раскладку из EN в RU» пока руками.
- **Удаление осиротевших файлов.** Файл, удалённый из библиотеки, но
  оставшийся на странице, превратится в битую ссылку — редактор об этом
  предупреждает, но сам связи не отслеживает.

## Секции стоят по той же сетке, что и остальной сайт

Боковой отступ секции лежит **внутри** её максимальной ширины, а не снаружи.
Разница в один отступ, и она была видна: контентная колонка страницы — это
`min(1240px, ширина окна)` с 20px внутри, а секция конструктора раньше была
`min(1240px, ширина окна − 40px)`, отцентрованная в окне. Ширины совпадали,
начало — нет, и заголовок страницы оказывался на 20px правее текста, который
админ ставил под ним. Настройки, которая бы это исправила, не существовало.

Теперь обе коробки — одна и та же коробка: элемент в нулевой колонке секции
начинается ровно там же, где `h1` страницы, хлебные крошки и логотип в шапке.
Проверяется одним измерением в консоли:

```js
const h1 = document.querySelector('main h1').getBoundingClientRect().left;
const block = document.querySelector('[style*="--rm-x"]').getBoundingClientRect().left;
h1 - block; // 0
```

## Заголовки в тексте

Выпадающий список в панели форматирования переключает блок между абзацем и
H1–H4. H1 нужен странице, целиком собранной конструктором: у неё нет другого
источника главного заголовка. На обычной странице H1 уже есть — второй будет
ошибкой, и вкладка «SEO и AI» в панели статистики её показывает.

Список типа блока и список размера шрифта — нативные `<select>`. Панель гасит
`mousedown`, чтобы не потерять выделение в тексте, но для полей ввода делает
исключение: открытие списка **и есть** действие по умолчанию его `mousedown`, и
без исключения оба списка выглядели рабочими и не делали ничего.
