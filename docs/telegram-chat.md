# Чат на сайте, связанный с Telegram

Виджет в правом нижнем углу. Посетитель пишет на сайте — сообщение приходит в
Telegram-группу поддержки; модератор отвечает прямо в Telegram — ответ появляется
у посетителя в виджете. Плюс кнопка «Продолжить в Telegram» для тех, кому удобнее
писать боту напрямую.

## Как это устроено

```
Посетитель ──POST /api/chat/message──►  Postgres  ──sendMessage──►  Telegram-группа
                                           ▲                              │
     GET /api/chat/messages (polling) ──────┘                              │
                                           ▲                              ▼
                                           └──POST /api/telegram/webhook──┘
```

Одна беседа = одна строка в `chat_threads` = **один топик** в супергруппе с
включёнными Topics. Поэтому несколько модераторов могут вести разные диалоги
параллельно и они не смешиваются в одну ленту.

### Почему polling, а не WebSocket/SSE

Виджет опрашивает `/api/chat/messages` раз в 5 секунд, **только пока панель
открыта и вкладка видима**. Долгоживущее соединение на каждого посетителя
держало бы память в контейнере, который тарифицируется по гигабайто-минутам, в
том числе для людей, оставивших вкладку в фоне.

### Порядок операций

`POST /api/chat/message` сначала сохраняет сообщение в БД и только потом
отправляет его в Telegram. Если Telegram недоступен или не настроен, посетитель
всё равно получает подтверждение доставки, а сообщение лежит в
`chat_messages` — оно не теряется.

### Как ответ находит свой тред

1. **`message_thread_id`** — топик, открытый под этого посетителя. Основной путь,
   от модератора ничего не требует.
2. **`reply_to_message`** — если группа не форумная, модератор отвечает реплаем
   на сообщение посетителя, и тред находится по сохранённому
   `telegram_message_id`.

Всё остальное игнорируется: обычная болтовня в группе не улетит посетителю.
Сообщения, начинающиеся с `/`, тоже игнорируются — это команды для модераторов.

## Модель данных

| Таблица | Назначение |
|---|---|
| `chat_threads` | Одна беседа. `token` — непредсказуемый идентификатор, выданный сервером; браузер предъявляет его, чтобы читать и дополнять **свой** тред. Плюс `telegram_chat_id` / `telegram_topic_id`, имя, контакт, локаль, страница, IP, UA. |
| `chat_messages` | Сообщения. `direction`: `in` — от посетителя, `out` — от модератора. `telegram_message_id` нужен для сопоставления реплаев. |

Токен генерируется **сервером** (`randomBytes(24)`), а не браузером: клиентский
идентификатор можно было бы подобрать и прочитать чужую переписку.

## Настройка

### 1. Создать бота

1. Напишите [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Задайте имя и username. Сохраните токен — это `TELEGRAM_BOT_TOKEN`.
3. `/setprivacy` → выберите бота → **Disable**. Иначе бот не увидит сообщения
   модераторов в группе и ответы не будут доходить до сайта.

### 2. Создать группу поддержки

1. Создайте **супергруппу** и включите в её настройках **Topics (Темы)**.
2. Добавьте бота в группу и сделайте его **администратором** с правом
   **Manage topics** (управление темами).
3. Узнайте id группы: перешлите любое сообщение из неё боту
   [@userinfobot](https://t.me/userinfobot), либо временно выставьте вебхук и
   посмотрите `chat.id` в логах. Id супергруппы отрицательный, вида
   `-1001234567890` — это `TELEGRAM_SUPPORT_CHAT_ID`.

> Если Topics не включить, всё продолжит работать: сообщения будут падать в общую
> ленту группы, а отвечать нужно **реплаем** на сообщение посетителя.

### 3. Переменные окружения

В Railway (и в `.env.local` для локальной разработки):

```
TELEGRAM_BOT_TOKEN=123456:ABC...
TELEGRAM_SUPPORT_CHAT_ID=-1001234567890
TELEGRAM_WEBHOOK_SECRET=<любая случайная строка>
NEXT_PUBLIC_SUPPORT_BOT_URL=https://t.me/ваш_бот
```

`TELEGRAM_WEBHOOK_SECRET` не обязателен, но без него эндпоинт вебхука принимает
запросы от кого угодно — то есть кто угодно сможет отправлять сообщения
посетителям от имени поддержки. Задавайте его.

### 4. Зарегистрировать вебхук

Telegram доставляет обновления по URL, который регистрируется один раз:

```bash
npm run telegram:webhook set
```

Проверить, что зарегистрировано:

```bash
npm run telegram:webhook info
```

Скрипт читает `NEXT_PUBLIC_APP_URL`, `TELEGRAM_BOT_TOKEN` и
`TELEGRAM_WEBHOOK_SECRET`. Повторяйте `set` после каждой смены домена или
секрета.

## Что происходит без настройки Telegram

Виджет остаётся рабочим: сообщения принимаются, сохраняются и видны в БД. Просто
никто не получит уведомление. Это осознанное решение — деградация, а не отказ.

## Ограничения

- Только текст. Файлы, фото и голосовые не передаются ни в одну сторону.
- История треда живёт в `localStorage` браузера: очистка хранилища или другой
  браузер = новый тред.
- Rate limit: 20 сообщений в минуту на IP на отправку, 90 запросов в минуту на
  опрос.
- Индикатора «прочитано» и «печатает» нет.
