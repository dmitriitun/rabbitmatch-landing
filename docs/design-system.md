# Дизайн-система

Светлая, плоская, контрастная. Референс — [myachmyach.ru](https://myachmyach.ru):
белый фон, чёрный текст, плоские цветовые блоки, крупная типографика.

## Чего здесь намеренно нет

Прошлая версия была тёмной с неоновыми акцентами. Это читается как
сгенерированный SaaS-лендинг и на мобильных стоит реального времени отрисовки.
Убрано и не должно возвращаться:

- размытые цветовые «блобы» (`filter: blur(80px)` под hero и секциями);
- градиентная заливка текста через `background-clip: text`;
- glassmorphism (`backdrop-filter` на карточках);
- свечения (`--glow-*`, `box-shadow` с большим цветным радиусом);
- canvas-подложка со звёздами, реагирующими на курсор;
- каскадные fade-in по скроллу на каждом блоке.

Осталось: сплошные заливки, границы в 1px и типографическая шкала.

## Токены

Объявлены в `src/app/globals.css` под `:root`.

| Группа | Переменные | Заметки |
|---|---|---|
| Текст | `--ink` `#0B0B0B`, `--ink-2` `#454545`, `--ink-3` `#7A7A78`, `--ink-inverse` | `--ink-2` для основного текста, `--ink-3` для подписей |
| Фон | `--bg` `#FFFFFF`, `--bg-subtle` `#F6F5F1`, `--bg-tint` `#F1FAD4`, `--bg-dark` `#0B0B0B` | `--bg-subtle` тёплый, чередует секции |
| Бренд | `--lime` `#B9E901`, `--lime-deep` `#7E9F00`, `--on-lime` | `--lime` только под чёрным текстом; `--lime-deep` — единственный оттенок лайма, проходящий 4.5:1 на белом |
| Линии | `--line` `#E3E2DD`, `--line-strong` | |
| Радиусы | `--radius-{sm,md,lg,xl,pill}` | 8 / 12 / 20 / 28 / 999 |
| Отступы | `--space-*` | шаг 4pt |
| Типографика | `--fs-{display,h1,h2,h3,lead,body,sm,xs}` | fluid через `clamp()` |
| Тени | `--shadow-{sm,md,lg}` | нейтрально-чёрные, без цвета |

### Про лайм

`#B9E901` на белом даёт контраст около 1.4:1 — как текст он нечитаем. Поэтому
он используется только как **фон под чёрным текстом** (кнопки, чипы, плашки).
Там, где лайм нужен именно как цвет текста или иконки на белом, берётся
`--lime-deep`.

## Шрифт

Onest, одна гарнитура на весь сайт, начертания 400/500/600/800, подмножества
latin + cyrillic. Одна гарнитура вместо пары — одна загрузка до первой
отрисовки; у Onest настоящая кириллица во всём диапазоне насыщенностей.

## Примитивы

Глобальные классы в `globals.css`, доступные из любого модуля:

- `.rm-container` — ширина и горизонтальные отступы;
- `.rm-section`, `.rm-section--{subtle,tint,dark}` — вертикальный ритм и тон;
- `.rm-btn`, `.rm-btn--{primary,lime,ghost}`;
- `.rm-card`, `.rm-eyebrow`, `.rm-lead`, `.rm-prose`, `.rm-sr-only`.

## Блоки страниц

`src/components/blocks/` — серверные компоненты, из которых собираются
контентные страницы:

| Блок | Что делает |
|---|---|
| `PageHero` | `<h1>` страницы, лид, список тезисов, две кнопки |
| `Section` / `SectionHead` | Обёртка секции и её заголовочная группа |
| `FeatureGrid` | Сетка карточек «иконка + заголовок + текст» |
| `AudienceGrid` | То же, но каждая карточка — ссылка на страницу аудитории |
| `Steps` | Нумерованный пошаговый список |
| `StatStrip` | Полоса из четырёх фактов |
| `Faq` | Аккордеон на `<details>` — без JavaScript |
| `CtaBand` | Тёмная полоса с призывом к действию |
| `AppBadges` | Кнопки App Store / Google Play / веб / Telegram |

Блоки **управляются контентом**: страница указывает ключ, а массив объектов
живёт в `messages/*.json`. Поэтому текст переводится и правится через админку, а
не через правку JSX. Иконки задаются строкой и резолвятся в
`blocks/icons.tsx`.

Пример:

```tsx
<Section tone="subtle" labelledBy="players-features">
  <SectionHead
    eyebrowKey="players.features.eyebrow"
    titleKey="players.features.title"
    headingId="players-features"
  />
  <FeatureGrid itemsKey="players.features.items" />
</Section>
```

## Экраны приложения на сайте

На сайте стоят настоящие скриншоты приложения. Файлы лежат в `public/app/`,
собираются из исходных захватов и подключаются одним компонентом:

```tsx
<AppShot name="games-list" priority />
```

`AppShot` берёт размеры из манифеста, а alt и подпись — из `messages/*.json`
(namespace `appShots`).

### Что делает сборка

**Только режет и сжимает.** Ничего не дорисовывает.

| Файл | Что делает |
|---|---|
| `scripts/app-shots.config.js` | Где искать захваты (верхний уровень, затем `копии скринов/`) |
| `scripts/app-shots.js` | Список: какой исходник, какой прямоугольник вырезать |
| `scripts/build-app-shots.js` | Собирает WebP в `public/app/` и пишет `manifest.json` |

```bash
npm run build:shots            # все
npm run build:shots games-list # один
```

Исходные захваты лежат **вне репозитория**, поэтому результат коммитится:
сборка сайта не должна зависеть от того, есть ли они на машине.

### Почему без заплаток

Предыдущая версия пайплайна умела рисовать поверх захватов: переводила
подписи, подменяла тестовые имена, дорисовывала аватарки. Получалось плохо —
размытые полосы под текстом, съехавшие края, залитые куски интерфейса. И даже
когда получалось аккуратно, скриншот, по которому прошлись кистью, перестаёт
быть доказательством.

Поэтому правило: **если на скриншоте что-то не то — переснять в приложении, а
не чинить в сборке.** Это относится и к языку интерфейса: чтобы получить
русские скриншоты, нужно переключить язык в приложении и сделать захваты
заново.

### Рамка телефона

Скриншоты без `crop` показываются в рамке с пропорциями настоящего iPhone
(19,5:9). Статус-бар с «островом» вшит в пиксели: контент ужимается на высоту
бара, бар рисуется сверху. Иначе остров лёг бы поверх собственной шапки
приложения.

Кропы (одна карточка, один блок статистики) показываются обычной карточкой без
рамки — половина экрана внутри телефона читается как сломанный телефон.

### Картинки не оптимизируются на лету

`images.unoptimized: true` в `next.config.ts`. Каждый файл уже WebP нужного
размера, оптимизатору нечего делать — а `sharp` тянет за собой арену libvips в
резидентную память постоянно работающего контейнера.

Кэш-заголовок у `/app/*` и `/images/*` намеренно короткий (час + неделя
`stale-while-revalidate`). Имена файлов не содержат хэша, а правило заголовков
применяется к любому ответу маршрута — включая 404. Месячный `max-age` однажды
уже привёл к тому, что CDN закэшировал 404 сломанного деплоя надолго после
того, как сам деплой починили.

## Вертикальный ритм

Отступы между секциями задаёт **только** `Section`:
`padding-block: clamp(56px, 8vw, 112px)`. Между двумя соседними секциями это
даёт двойную величину — это и есть шаг ритма страницы.

Из этого следует правило: **компонент, который кладут внутрь `Section`, своих
секционных отступов иметь не должен.** `Pricing` и `Comparison` умеют и то и
другое: без пропсов рисуют собственную секцию с заголовком, с `bare` — только
содержимое. Обе страницы, где они стоят, используют `bare`, потому что
заголовок над ними уже даёт `SectionHead`. Пока было иначе, на странице
тарифов было два `h2` подряд и 280 px пустоты между ними.

Фоны секций чередуются: `default` → `subtle` → `default`. Две подряд с
одинаковым фоном сливаются в одну полосу, и двойной отступ посреди неё
читается как дыра в вёрстке.

## Правило про ссылки

Все внутренние переходы — через `Link` из `@/i18n/navigation`, а не из
`next/link`: он сам подставляет префикс локали. `next/link` уведёт на URL без
префикса, который отработает редиректом и потеряет выбранный язык.
